# Signed macOS Builds & Working Auto-Updater

This release closes two large gaps in the desktop distribution: macOS Gatekeeper now trusts the app out of the box, and the in-app auto-updater is wired up end-to-end for the first time. (Tag `beta.4` was a partial release where the Windows build failed at signing — beta.5 supersedes it.)

## Highlights

- **macOS: signed and notarized** — The DMG is now signed with a Developer ID Application certificate and notarized by Apple. On first launch you'll see a single "Are you sure you want to open?" prompt instead of the previous "Apple cannot check this for malicious software" warning. No more right-click-Open workaround.
- **Auto-updates now work** — Previous betas were silently shipping without a valid `latest.json`, so the in-app updater could never detect a new version. The Tauri v2 `createUpdaterArtifacts` opt-in was missing — adding it (together with the `app` bundle target on macOS) makes the build produce properly-named updater bundles and signatures, which the release workflow then publishes to the update endpoint.

## Heads-up for existing beta users (macOS)

The bundle identifier changed from `com.maravillalabs.konto` to `cloud.maravilla.konto` to match the new App ID registered in our Apple Developer account. macOS treats this as a different application, so:

- The old beta.3 build will remain in `/Applications` until you delete it manually.
- The new beta.5 build starts with a fresh app sandbox — settings, cached data and local storage from beta.3 will not carry over.
- The in-app updater can't bridge this transition; download beta.5 manually from the Releases page one final time. Updates from beta.5 onwards will install automatically.
